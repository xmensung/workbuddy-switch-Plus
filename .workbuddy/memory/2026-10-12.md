## 排查「积分悬浮窗环形图不出现」（用户反馈）

### 结论：功能代码本身无误，真实缺陷是浮窗未显式定位

用「Rust 落盘探针」做了确定性验证（临时命令 `wb_probe` + `probe_log`，验证完已删除）：

- 主窗口 DOM 探针：`hasBtn=true` —— 底部栏 ✦ 按钮**确实渲染出来了**

## 第二轮：用户装 v0.1.61 后仍报「没有环形图 + 不能拖动」

用户原话：「你这个悬浮窗，既没有我要的环形图，也不能随便挪位置，在搞什么？？？」

### 关键推理：环形图一枚都不出现 ⇒ 渲染的根本不是 CreditFloatPage

`CreditFloatPage` 里 `CreditRing` 是无条件渲染的：即使账号为空、积分未到，也会画出
底色环（比例 0%）。所以「一枚环都看不到」只有两种解释——要么整个主界面被渲染进了
小窗（主界面 Windows 下无拖拽区 ⇒ 顺带解释「不能拖动」），要么错误页。
查 `~/.wb-switch/error.log` **不存在** ⇒ 没有渲染期崩溃 ⇒ 结论是**渲染成了主界面**。

### 根因：悬浮窗与主窗口共用 index.html，靠运行期窗口 label 分流

`WebviewUrl::App("index.html")` 让两个窗口加载同一份文档，渲染哪棵 React 树完全押在
`isCreditFloatWindow()` 上。这个判定在打包环境下一旦不成立（宿主差异 / 资源解析回退 /
脚本顺序），悬浮窗就会渲染出整套应用，且**没有任何编译期约束能拦住它**。

### 修复（v0.1.63）：把不确定性从运行期挪到构建期

1. **独立页面入口**：新增根级 `credit-float.html` + `src/credit-float.tsx`；
   `vite.config.ts` 配 `build.rollupOptions.input`（main + creditFloat）双入口；
   Rust 改 `WebviewUrl::App("credit-float.html")`。这份 bundle 里根本没有主界面。
   —— `main.tsx` 的 label 分流**保留**作为第二道防线（万一 `credit-float.html`
   解析失败回退到 index.html，label 判定仍能兜住）。
2. **整卡可拖**：`CreditFloatPage` 新增 `useWindowDrag()`，在卡片容器上补手动
   `getCurrentWindow().startDragging()`；命中 `button/a/input/select/textarea/
   [data-tauri-drag-region]` 时放行。旧版只把 `data-tauri-drag-region` 挂在细窄的
   标题栏上，用户按住卡片正文拖当然没反应——这就是「不能随便挪位置」的体感来源。
3. **账号列表与运行状态解耦**：`stores/accounts.ts` 的 `fetchAll` 原来把
   `getAccounts()` 与 `getStatus()` 放进同一个 `Promise.all`，任一失败都会让
   `accounts` 保持为空 ⇒ 悬浮窗退化成空态、看不到环。改为各自 `catch` 后合并。

## v0.1.67：托盘指针行为 + 刷新时间 + 双击环跳转（22:20 起）

用户三条：
1. 鼠标悬停托盘图标就弹出浮窗、单击显示浮窗、双击显示主界面；
2. 浮窗右上角刷新后贴出刷新时间；
3. 双击圆环跳到主界面积分详情页。

### 1) 托盘指针行为（`src-tauri/src/tray.rs`）

- `on_tray_icon_event` 重写：`Enter` → `credit_float::show(app, false)`（**不抢焦点**，
  `show()` 只做 SWP_SHOWWINDOW，不激活窗口）；左键抬起 → 打开浮窗；左键 `DoubleClick`
  → `show_main_window`。macOS 仍旧行为（左键留给菜单），由
  `tray_pointer_actions_enabled()` 统一门控（原来的 `should_wake_main_window` 已删）。
- **关键坑：Windows 给一次双击派发的是 Down → Up → DBLCLK → Up**（`tray-icon` 0.24.2
  的 `platform_impl/windows/mod.rs` 里 `WM_LBUTTONDBLCLK` 与 `WM_LBUTTONUP` 都发事件）。
  先来一次完整单击抬起、DBLCLK 之后还补一次抬起。若两者都直接落地，双击会「先闪浮窗、
  主界面之上又冒一次浮窗」。因此新增 `TrayClickArbiter`：
  - 单击 → `Defer(generation)`，延迟 `TRAY_CLICK_DOUBLE_WINDOW_MS = 400ms` 再落地；
  - 双击 → generation += 1（作废挂起的单击）+ 记录时刻，随后 400ms 内的单击返回 `Ignore`。
  - 时钟用 `Instant`（`tray_clock_ms()`，进程启动为 0），不受系统时钟调整影响。
  - 6 条单测覆盖：挂起后落地 / 双击作废挂起 / 余波丢弃 / 窗口外算新点击 / 新点击顶替旧
    挂起 / 时钟单调。
- **`show_or_focus(app, focus)` 加了 focus 参数**，并且**只在窗口由不可见转为可见时才
  `emit(VISIBILITY_EVENT)` + `refresh_tray_menu`**：悬停会反复走到这里，而菜单正在展示时
  `set_menu` 会让它闪掉（原代码注释里就写了「不要在指针进入/点击回调里重建菜单」）。
- 托盘回调里 `AppHandle` 用**具体类型**（`Wry`）而不是泛型：`TrayIconBuilder::with_id`
  未指定 runtime，`credit_float::show/toggle` 又是具体 `AppHandle`，泛型会对不上。

### 2) 刷新时间（`CreditFloatPage.tsx`）

- 头部右侧、刷新按钮左边贴 `HH:MM:SS 刷新`；刷新中显示「刷新中…」。
- 时间优先用**本机手动刷新的时刻** `refreshedAt`，没有则退回各账号 `credit.updatedAt`
  的最大值（`lastSyncedAt`）——窗口打开时的补齐、30 分钟后台刷新都不经过手动按钮，
  只看本机时间戳会把「上次刷新」显示错。

### 3) 双击环 → 积分统计页

- Rust 新增 `open_credit_stats`：`tray::show_main_window`（已提升 `pub(crate)`）+

## v0.1.68：托盘悬停预览「指针移开即消失」（23:00 起）

用户一条：鼠标移到托盘图标上 → 浮窗出现；鼠标移开 → 浮窗自动消失。

### 核心概念：窗口来源分两种

新增 `HOVER_PREVIEW: AtomicBool`（`credit_float.rs`）——只有**悬停预览**才自动收起；
底部按钮 / 托盘菜单 / 单击托盘图标都是**显式打开**，移开指针不该把它们关掉。
窗口已经显式打开时再悬停托盘图标也不会把它降级成预览（`show_or_focus` 里只在
「本次才显示出来」或「本次是显式打开」时改写这个标记）。

### 收起判定：轮询 + 重置计时，不是一次性定时器

`TrayIconEvent::Leave` → `credit_float::on_pointer_left_tray` → spawn 一个 110ms 的轮询任务，
由 `HoverWatch` 判定：**指针连续 `HOVER_HIDE_DELAY_MS = 350ms` 都不在窗口范围内**才收起。

**为什么不能是一次性定时器**：指针从托盘图标移向浮窗的路上，有一段时间既不在图标上
也不在窗口上——一次性判定会在这段路上就把窗口收掉，用户根本来不及把鼠标挪过去。
改成「探到在窗内就重置计时」，于是「移开就消失」和「移过去能用」同时成立。

### 位置判定用 Rust 读光标，不用前端 mouseleave

`AppHandle::cursor_position()`（底层 `GetCursorPos`）+ `window.outer_position()` /
`outer_size()`（底层 `GetWindowRect`）——**两者都是虚拟屏幕物理像素**，可直接比较，
多显示器负偏移与缩放都不会错位（已核对 tao 0.35.3 的 windows 实现）。
不用前端事件的原因：悬浮窗为了不抢焦点从来不是激活窗口，未获焦点的 webview 能否
稳定收到鼠标进出事件没有保证；而光标位置随时可读。

### 预览收起只 `hide()`，不销毁窗口

指针再次移入托盘图标时要「立刻」显示——建窗（WebView2）要几百毫秒，悬停场景下那一下
很明显；保留 WebView 也省掉重新拉账号数据。**因此 `is_open()` 必须改成按可见性判定**
（原来是「窗口对象是否存在」），否则隐藏状态的窗口会让托盘勾选与底部按钮显示成「开着」。

### 显式打开的收尾

`enter_pinned_mode()`：清预览标记 + 代次 +1（让挂起的收起轮询自行退出）。
`TrayClickAction::ShowFloat` 变体删除（Enter 不再走仲裁，直接 `show_preview`）。
