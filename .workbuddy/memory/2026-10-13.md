## v0.1.69：3 天内到期逐笔列出 + 修掉「今天到期」被误判失效（19:00 起）

### 用户要求（截图红框）

灰色那句 `10-17 到期 · 5 天后，另有 N 个到期日` 不要了，改成在灰色文字位置
**逐笔写出 3 天内到期的积分及数额**。

### 实现

`CreditFloatPage.tsx`：
- `AccountSummary` 新增 `urgent: UrgentEntry[]`（`{amount, expireAt, label}`）——
  3 天内到期的积分包**逐笔保留、不按到期日合并**（用户要看的是「哪几笔、各多少」）。
- 新增 `URGENT_DAYS = 3`，与 `SOON_DAYS = 7` 并存。
- `SoonNotice` 分三态：
  - 7 天内无到期 → 「7 天内没有到期的积分」
  - **有 3 天内到期 → 红字合计 + 逐笔列表**：`90 · 资源包 1 · 10-14 到期 · 1 天后`
  - 只有 3 天外 7 天内 → 保留原来的合计 + 最近到期日
- 明细行用 **flex 三段布局**（金额 / 包名 / 到期日）：包名 `flex-1 truncate` 先让位，
  金额与到期日 `shrink-0 whitespace-nowrap` 永远完整。原先单行 `·` 拼接在窄窗口下
  会把「今天到期」截成「今天…」。

### 顺带修掉一个真 bug：「今天到期」的积分被误判为已失效

`isExpired` 原来拿 `expireAt <= now` 判过期，而官方给的 `expireAt` 是**到期日当天 00:00**。
结果：**只要过了当天零点，当天到期的包就被整笔剔除**——既不计入可用积分，也不在
「3 天内到期」里露面。用户截图里 `19081287917` 环心只显示 2,600（真实 4,800），
「今天到期」的 2,200 直接消失，就是这个原因。

**改成整天口径**：新增 `startOfDay()` / `daysUntil()`（今天到期 = 0），
`isExpired` 改为 `startOfDay(expireAt) + DAY_MS <= startOfDay(now)` ——
到期日当天仍然可用，过了次日零点才失效。`toneOf` / `formatLeft` / 紧急窗口判定
全部统一到 `daysUntil`，避免同一屏里两种天数口径打架。

修复后同一份数据：环心 2,600 → **4,800**，明细里出现「2,200 · 基础版资源包 · 10-13 到期 · 今天到期」。
